Overview

In this assignment you will transform the provided starter into a complete JavaFX implementation of Connect Four. The emphasis is not only on making the program work, but on organizing the solution using MVC plus the required design patterns.

The final program should support a graphical Connect Four game, multiple player/opponent types, undo/redo, and save/load functionality. Your code should be clean, modular, and easy to extend.

Design goal: your solution should show clear separation of responsibilities. Avoid giant classes, duplicated logic, and view code mixed into the model.

Required features

  • JavaFX GUI for Connect Four
  • Use the MVC pattern to organize the application
  • Human vs Human mode
  • Support for other opponent/player types through the Strategy pattern
  • GUI controls allowing the user to select player/opponent types
  • Undo and redo using the Command pattern
  • Game restart/reset
  • Save game to file
  • Load game from file
  • Status area showing messages such as current player, winner, draw, invalid move, and loaded/saved state
  • JUnit tests for important parts of the model

Required patterns and architectural expectations

Pattern / ideaExpectation in this assignment
MVCThe model must represent game state and rules; the view displays the state; controllers/event handlers react to GUI input and coordinate actions.
StrategyDifferent player behaviours such as human, random, greedy, or other strategies should be swappable without rewriting the rest of the game.
CommandMoves should be represented as commands, making undo and redo natural and structured rather than ad hoc.
Observer / notificationsThe provided observable/observer utilities may be used to keep views synchronized with the model.

Marking rubric (100 marks)

CategoryMarksWhat we are looking for
MVC architecture 25 Clear separation between model, view, and controller/event-handling code; minimal coupling; no major architectural confusion; model not dependent on JavaFX presentation details.
Strategy pattern 15 Opponent/player types are represented cleanly as interchangeable strategies; selection is supported through the GUI; extension to new strategies is straightforward.
Command pattern / undo-redo 15 Moves are encapsulated cleanly as commands; undo/redo behaves correctly and consistently; implementation is structured and not hard-coded in the GUI.
Connect Four functionality and correctness 20 Valid move handling, win/draw detection, turn changes, restart behaviour, and general game correctness; save/load works reasonably and restores game state correctly.
JavaFX GUI quality 10 GUI is functional, readable, and easy to use; board updates correctly; controls and status information are clear.
Code quality and documentation 10 Meaningful naming, appropriate decomposition into classes/methods, useful comments/JavaDoc, and a brief explanation of how the classes participate in MVC and the required patterns.
Testing 5 JUnit tests cover core model behaviour and are expanded beyond the supplied starter tests.

Rubric interpretation

  • Excellent: patterns are clearly recognizable, responsibilities are well separated, and the code is easy to extend.
  • Good: solution works well and patterns are mostly clear, with only minor design or code-quality issues.
  • Satisfactory: core features work, but architectural separation or pattern usage is partial or inconsistent.
  • Weak: major features missing, or the code works only in a fragile or poorly organized way.
